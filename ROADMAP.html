Project blueprint · Windows 11 · Local-first

Local AI Assistant

Roadmap สำหรับสร้างต้นแบบบน Acer Swift Go SFG14-41-R2QM ก่อน แล้วจึงย้ายหรือปรับประสิทธิภาพบนเครื่องหลัก โดยคงแนวคิดออฟไลน์เป็นค่าเริ่มต้นและไม่ผูกระบบกับฮาร์ดแวร์เครื่องใดเครื่องหนึ่ง

ต้นแบบ: Acer Swift GoDesktop: Tauri + Vue 3Backend: Python + FastAPILocal LLMภาษาไทยเป็นหลัก

เป้าหมายผลิตภัณฑ์

  • คุยได้ 3 รูปแบบ: Push-to-Talk, Hands-Free, Wake Word
  • ทำงานในเครื่องเป็นค่าเริ่มต้น ไม่เรียก Cloud ระหว่างสนทนา
  • มีความจำระยะยาวที่ผู้ใช้ตรวจสอบ แก้ไข และลบได้
  • คำสั่งที่มีผลต่อไฟล์หรือระบบต้องขออนุมัติก่อน
  • เตรียมโมดูลออนไลน์ไว้ แต่ปิดและไม่เชื่อมต่อในช่วงต้นแบบ

ฮาร์ดแวร์และข้อควรระวัง

เครื่องต้นแบบAcer Swift Go SFG14-41-R2QM
เครื่องเป้าหมายภายหลังRyzen 5 5600X · RAM 32GB · RTX 5060 Ti 8GB
แนวทางตรวจสเปกจริงของ Swift Go ก่อนเลือกโมเดล

ประสิทธิภาพ LLM และการเร่งด้วย GPU ของเครื่องต้นแบบขึ้นกับ CPU, RAM, GPU และระบบระบายความร้อนของรุ่นย่อยจริง จึงยังไม่กำหนดขนาดโมเดลตายตัว

Roadmap การพัฒนา

0

สำรวจเครื่องและกำหนด baseline เริ่มต้น

  • ตรวจ CPU, RAM, GPU, พื้นที่ว่าง, Windows และไดรเวอร์
  • ตรวจ Python, Node.js, Git, Ollama และโมเดล Qwen ที่มีอยู่
  • บันทึกเวอร์ชันและผลทดสอบก่อนเปลี่ยนแปลงระบบ
ผลลัพธ์: รายงานสภาพแวดล้อมและรายการสิ่งที่ต้องติดตั้ง โดยยังไม่ลบของเดิม
1

วางโครงโปรเจกต์และรันแอปเปล่า

  • สร้าง repository และโครงสร้าง apps / services / docs
  • สร้าง Tauri + Vue 3 + TypeScript พร้อมหน้า Chat และ Dashboard เปล่า
  • สร้าง FastAPI health endpoint และระบบ log
  • ให้ Desktop ติดต่อ Backend ผ่านช่องทาง Local ที่กำหนด
ผลลัพธ์: เปิด Desktop App ได้และตรวจสถานะ Backend ได้
2

เชื่อม LLM ภายในเครื่อง

  • ตรวจโมเดลเดิมและเลือกโมเดลที่เหมาะกับทรัพยากรเครื่องต้นแบบ
  • เชื่อมผ่าน Local API และแสดง token streaming ถ้ารองรับ
  • เพิ่มการเลือกโมเดล การหยุดสร้างคำตอบ และการจัดการข้อผิดพลาด
  • ทดสอบโดยตัดอินเทอร์เน็ตหลังเตรียมไฟล์ครบ
ผลลัพธ์: แชตข้อความกับโมเดล Local ได้โดยไม่ใช้ Cloud
3

ประวัติสนทนาและข้อมูล Local

  • ออกแบบ SQLite schema สำหรับ conversations และ messages
  • เพิ่มค้นหา เปลี่ยนชื่อ ลบ และเริ่มบทสนทนาใหม่
  • กำหนดตำแหน่งเก็บข้อมูลและวิธีสำรอง/ส่งออก
ผลลัพธ์: ประวัติสนทนาคงอยู่หลังปิดและเปิดแอปใหม่
4

Voice: Push-to-Talk

  • เลือกอุปกรณ์ไมโครโฟนและทดสอบการรับเสียง
  • เพิ่ม STT และประเมินความแม่นยำภาษาไทย
  • เลือก TTS ที่ออกเสียงภาษาไทยได้เหมาะสม
  • เพิ่มปุ่มกดพูด หยุดฟัง เล่นซ้ำ และสถานะการประมวลผล
ผลลัพธ์: กดพูด → ถอดข้อความ → AI ตอบ → อ่านคำตอบเป็นเสียง
5

Voice: Hands-Free Conversation

  • เพิ่ม VAD เพื่อตรวจจับช่วงเริ่มพูดและหยุดพูด
  • ปรับ endpointing และช่วงรอหลังผู้ใช้พูดจบ
  • ป้องกันเสียง TTS ย้อนเข้าไมโครโฟน
  • รองรับการพูดแทรกและยกเลิกคำตอบเดิม
ผลลัพธ์: สนทนาต่อเนื่องได้โดยไม่ต้องกดปุ่มทุกครั้ง
6

Voice: Wake Word

  • เลือกตัวตรวจจับคำปลุกที่ทำงานในเครื่อง
  • ทดสอบคำปลุกในสภาพแวดล้อมจริงและลด false activation
  • เพิ่มสถานะ standby, listening และปุ่มปิดไมโครโฟน
  • กำหนดให้ Wake Word ส่งต่อเข้าสู่โหมดสนทนาที่ผู้ใช้เลือก
ผลลัพธ์: เรียกผู้ช่วยด้วยคำปลุกได้ โดยควบคุมการฟังได้ชัดเจน
7

Long-term Memory และ Privacy

  • แยกประวัติสนทนาออกจากความจำระยะยาว
  • ให้ผู้ใช้เลือกบันทึก ตรวจสอบ แก้ไข และลบความจำ
  • กำหนดการลบข้อมูลต้นทางและข้อมูลที่เกี่ยวข้อง
  • ไม่บันทึกเสียงดิบเป็นค่าเริ่มต้น
ผลลัพธ์: AI เรียกใช้ความจำที่ผู้ใช้อนุญาตได้ และผู้ใช้ควบคุมข้อมูลได้
8

Permission Manager และ Extensions

  • กำหนดสิทธิ์เครื่องมือแบบ allowlist
  • แสดงรายละเอียดการกระทำและขออนุมัติก่อนทำสิ่งสำคัญ
  • แยกเครื่องมือเป็นโมดูล พร้อมบันทึก audit log
  • ยังไม่เปิดให้ LLM รัน PowerShell หรือคำสั่งระบบอย่างอิสระ
ผลลัพธ์: เพิ่มเครื่องมือได้โดยมีขอบเขตและจุดอนุมัติชัดเจน
9

ทดสอบ Offline และย้ายไปเครื่องหลัก

  • ทดสอบตัดอินเทอร์เน็ตและตรวจการเชื่อมต่อออก
  • ทดสอบการทำงานต่อเนื่อง การใช้ RAM/VRAM และความร้อน
  • ย้ายข้อมูลที่จำเป็นและติดตั้งโมเดลที่เหมาะกับ RTX 5060 Ti
  • เตรียมแพ็กเกจ Desktop และวิธี backup/restore
  • คง External Integration เป็น Disabled จนกว่าจะอนุมัติเปิดใช้
ผลลัพธ์: ต้นแบบพร้อมย้ายเครื่องและมีเกณฑ์ตรวจรับก่อนใช้งานจริง

หลักการออกแบบ UI

  • Chat เป็นหน้าแรก: เน้นพื้นที่สนทนาและประวัติ
  • Dashboard แยก: สถานะโมเดล เสียง GPU/RAM และ log
  • Voice Studio: อุปกรณ์เสียง โหมด และการทดสอบ
  • Memory: รายการความจำพร้อมแก้ไข/ลบ
  • Settings: Privacy, Startup, Storage และ Diagnostics

เกณฑ์ความปลอดภัย

  • Backend เป็นผู้ตรวจสิทธิ์ ไม่เชื่อ UI อย่างเดียว
  • ผูกบริการ Local กับ loopback และป้องกันการเข้าถึงจากเครือข่ายอื่น
  • ปิด Cloud/Telemetry/Sync ที่ไม่จำเป็น
  • มีปุ่มหยุดฟังและตัวบ่งชี้ไมค์ชัดเจน
  • ขออนุมัติก่อนแก้ไข/ลบไฟล์หรือเปลี่ยนค่าระบบ
ข้อควรจำก่อนเริ่ม: ชื่อรุ่น Acer Swift Go SFG14-41-R2QM ยังไม่เพียงพอที่จะฟันธงประสิทธิภาพ AI ต้องตรวจ CPU, RAM และ GPU ของเครื่องจริงก่อนเลือกโมเดล โดยต้นแบบควรพิสูจน์สถาปัตยกรรมและ workflow ก่อน ไม่จำเป็นต้องเร่งให้โมเดลใหญ่หรือเสียงทุกส่วนทำงานบน GPU พร้อมกันตั้งแต่วันแรก
